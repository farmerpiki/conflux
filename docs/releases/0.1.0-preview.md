# Conflux 0.1.0 Preview

Status: draft release notes for the first public preview.

## Scope

Preview package components:

- `core`
- `json`
- `file_io_sync`
- `http`, only from real-liburing builds with runtime evidence attached
- `work`, only from real-liburing builds with runtime evidence attached
- `pg`, only when the PostgreSQL proof/evidence run is attached and green

Preview SKUs:

- `release-json`: `core`, `json`, `file_io_sync`
- `release-http-api`: `core`, `json`, `http`
- `release-web-server`: `core`, `json`, `http`

Recommended producer feature bundles:

- `core`
- `json`
- `http-minimal`
- `http-api`

Experimental or conditional components and bundles should not be advertised as
the default entry point for first-contact users: HTTP/2, HTTP/3, P2996
reflection, SEND_ZC tuning, and the full `complete` aggregate surface.
PostgreSQL pipeline support may be advertised with `pg` only when the
PostgreSQL integration and pipeline evidence run is attached and green.

## Platform

Conflux is Linux-only and `io_uring`-first. A usable `io_uring` runtime and
`liburing` development package are required for runtime-facing components,
including HTTP server/client components, async file I/O, socket I/O, and the
tests and benchmarks that exercise those surfaces. The `core`, `json`,
`file_io_sync`, and `file_map` component surfaces remain liburing-free.
Liburing-free installs advertise only dependency-light components for generated
header artifact checks and intentionally do not publish runtime-facing
components such as `work` or `http`.

Conflux is modules-first. C++ module consumption is toolchain-sensitive, so use
the checked-in CMake presets as the support matrix for this preview. The
intended preview floor is GCC 15, GCC 16, Clang 21, CMake 4.2+, and Ninja; do
not treat arbitrary compiler/version combinations or older CMake versions as
supported unless they configure, build, and pass the matching tests in release
evidence. GCC 15 is the no-LTO release lane; GCC 16 and Clang 21 are the
LTO-capable release lanes; GCC 16 is the current P2996 reflection lane.

Container or seccomp policies can block runtime setup even on a new kernel.
Runtime capability probes and test results are the release evidence source of
truth.

## Install And Consume

The prerelease primary source-consumption mode is `MODULE_INTERFACE`:

```cmake
find_package(conflux REQUIRED COMPONENTS http json)
target_link_libraries(app PRIVATE conflux::http conflux::json)
```

Generated headers are staged release artifacts for header-mode consumers that
cannot use modules and are generated from the same module sources. Header mode
is supported only for the components and toolchains covered by
package-smoke evidence; other uses are best-effort:

```cmake
find_package(conflux REQUIRED COMPONENTS core json file_io_sync)
target_link_libraries(app PRIVATE conflux::core conflux::json conflux::file_io_sync)
```

## Supported Components

- Liburing-free install: `core`, `types`, `json`, `file_io_sync`.
- real-liburing install: may add runtime-facing package components such as
  `work` and `http`.
- DB-off install: no generated DB headers and no `db` / `pg` package contract.
- DB-on install: `pg` only when libpq is available and DB evidence is attached.
  `db` is not an advertised preview package component.

## API Stability

This is a pre-v1 preview. APIs may still break before v1. Public examples and
docs should use final preview names only. Deprecated compatibility aliases are
not part of the advertised surface.

## Evidence

Attach release evidence artifact paths separately before tagging. Leave these as
placeholders until the release-candidate source tree is frozen; any benchmark
artifact cited by the notes must reference the actual tagged candidate commit,
not an earlier development snapshot.


- configure/build/test logs for the advertised compiler lanes;
- package-config smoke result;
- staged modules-first release artifact result from
  `scripts/stage-release-artifacts.sh`;
- example compile result;
- PostgreSQL integration/pipeline evidence when `pg` is advertised;
- benchmark artifacts only for explicit performance claims.

Checks to attach before tagging:

- `scripts/stage-release-artifacts.sh --stage-dir /tmp/conflux-release-artifacts/stage --no-tarball`
- `scripts/check-package-smoke-runtime.sh`, or an explicit liburing skip reason
- `scripts/check-package-smoke-db.sh`, or an explicit libpq/DB skip reason
- first-contact docs and public examples guards from `docs/release-checklist.md`

## Migration Notes

Public examples and first-contact docs use final preview spellings. Historical
short aliases and removed async/sync names are tracked in migration docs; they
are not promoted as the preview API.

## Known Limitations

- Linux only.
- Runtime-facing and HTTP packages require real liburing.
- C++ module consumption is primary and toolchain-sensitive.
- Supported toolchains are intentionally narrow and tied to release evidence.
- Generated headers are header-mode artifacts, not hand-maintained source or
  the design center for new APIs.
- Optional protocol and DB support depends on detected system libraries.
- Third-party protocol conformance and external OpenAPI validator results must
  be attached separately before making conformance claims.
- Full JSONTestSuite classification, parser differential testing, and public
  JSON benchmark proof are not bundled in this source tree.
- Benchmark logs are external evidence, not bundled here.

## Benchmark Claims Policy

Do not make performance claims without same-machine benchmark artifacts. Release
notes may cite benchmark artifact paths after the final benchmark run is
attached, but raw bulky logs stay outside the tracked source tree. Benchmark
graphs should be generated from that final artifact set just before tagging so
they reflect the released source state.
