# Conflux 0.1.0 Preview

Status: draft release notes for the first public preview.

## Scope

Advertised components for the preview:

- `core`
- `json`
- `http-minimal`
- `http-api`
- `pg`, if the PostgreSQL proof/evidence run is attached and green

Experimental or conditional components should not be advertised as the default
entry point for first-contact users: HTTP/2, HTTP/3, P2996 reflection,
SEND_ZC tuning, and full `complete/current` bundles. PostgreSQL pipeline support
may be advertised with `pg` only when the PostgreSQL integration and pipeline
evidence run is attached and green.

## Platform

Conflux is Linux-only and `io_uring`-first. A usable `io_uring` runtime and
`liburing` development package are required for runtime-facing components,
including HTTP server/client components, async file I/O, socket I/O, and the
tests and benchmarks that exercise those surfaces. The `core`, `json`,
`file_io_sync`, and `file_map` component surfaces remain liburing-free.
`CONFLUX_USE_MOCK_LIBURING=ON` is build-tree compile evidence only; installed
mock-liburing packages advertise liburing-free components and intentionally do
not publish `runtime` or `http`.

C++26 modules support is toolchain-sensitive. Use the checked-in CMake presets
as the support matrix for this preview; do not treat arbitrary compiler/version
combinations as supported unless they configure, build, and pass the matching
tests.

Container or seccomp policies can block runtime setup even on a new kernel.
Runtime capability probes and test results are the release evidence source of
truth.

## Install And Consume

The prerelease package-consumption baseline is `HEADER_INTERFACE`:

```cmake
find_package(conflux REQUIRED COMPONENTS core json file_io_sync)
target_link_libraries(app PRIVATE conflux::core conflux::json conflux::file_io_sync)
```

Runtime/http consumers need a real-liburing install:

```cmake
find_package(conflux REQUIRED COMPONENTS core json http runtime)
target_link_libraries(app PRIVATE conflux::core conflux::json conflux::http conflux::runtime)
```

## Supported Components

- Mock-liburing install: `core`, `types`, `json`, `file_io_sync`.
- Real-liburing install: may add `runtime` and `http`.
- DB-off install: no generated DB headers and no `db` / `pg` package contract.
- DB-on install: `db` only when libpq is available and DB evidence is attached.

## API Stability

This is a pre-v1 preview. APIs may still break before v1. Public examples and
docs should use final preview names only; deprecated compatibility aliases are
not part of the advertised surface.

## Evidence

Attach proof/evidence artifact paths separately before tagging:

- configure/build/test logs for the advertised compiler lanes;
- package-config smoke result;
- example compile result;
- PostgreSQL integration/pipeline evidence when `pg` is advertised;
- benchmark artifacts only for explicit performance claims.

Checks to attach before tagging:

- `scripts/check-package-smoke-liburing-free.sh`
- `scripts/check-package-smoke-runtime.sh`, or an explicit liburing skip reason
- `scripts/check-package-smoke-db.sh`, or an explicit libpq/DB skip reason
- first-contact docs and public examples guards from `docs/release-checklist.md`

## Migration Notes

Public examples and first-contact docs use final preview spellings. Historical
short aliases and removed async/sync names are tracked in migration docs and
planning archives; they are not promoted as the preview API.

## Known Limitations

- Linux only.
- Runtime/http packages require real liburing.
- C++ module consumption is toolchain-sensitive.
- Optional protocol and DB support depends on detected system libraries.
- Runtime proof and benchmark logs are external evidence, not bundled here.

## Benchmark Claims Policy

Do not make performance claims without same-machine benchmark artifacts. Release
notes may cite benchmark artifact paths, but raw bulky logs stay in the ignored
local evidence directory or separate proof repository.
