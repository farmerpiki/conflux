## Tests doing wrong / too-weak checks

1. **DONE: HTTP façade compile-fail tests can pass for the wrong reason**

   * `tests/http_facade_compile_fail_file_free.cxx`
   * `tests/http_facade_compile_fail_offload_free.cxx`
   * `tests/http_facade_compile_fail_openapi_handler_free.cxx`
   * Problem: tests use `http::file`, `http::offload`, `http::openapi_handler`, but no `namespace http = conflux::http;`.
   * Result: compile failure can be “`http` not declared,” not “helper correctly hidden from façade.”
   * Fix: use `conflux::http::...` or add namespace alias; import needed modules explicitly.

2. **DONE: Compile-fail matcher accepts generic substrings**

   * `scripts/check-compile-fail-target.sh`
   * `tests/CMakeLists.txt`
   * Problem: checks strings like `WorkPool`, `Router`, `file`, `offload`.
   * Result: unrelated compiler errors, source echoes, import failures, or suggestions can satisfy test.
   * Fix: use unique expected diagnostics via `static_assert`/concept failure text, or paired positive/negative compile tests.

3. **DONE: Dynamic gzip test does not verify valid gzip**

   * `tests/compression_matrix_e2e.cxx`
   * Problem: checks compressed body is non-empty and not equal to original.
   * Result: arbitrary garbage passes.
   * Fix: decompress response and assert exact original payload.

4. **DONE: Precompressed sidecar test uses fake `.gz` / `.br` bytes**

   * `tests/compression_matrix_e2e.cxx`
   * Problem: writes `"gzip-sidecar"` / `"brotli-sidecar"` and expects those bytes with `Content-Encoding`.
   * Result: proves sidecar selection, not valid HTTP precompressed content.
   * Fix: write real compressed sidecars; verify raw transfer plus decompressed identity payload.

5. **OpenAPI tests use substring checks instead of parsing JSON**

   * `tests/http_e2e_observability.cxx`
   * Problem: searches for `"openapi":"3.0.0"`, paths, params, etc.
   * Result: invalid JSON/OpenAPI can pass if substrings appear.
   * Fix: parse JSON and assert exact structure; optionally run external OpenAPI validator.

6. **Proxy hostile-upstream cases all assert same generic failure**

   * `tests/proxy_hostile_upstream_e2e.cxx`
   * Problem: mid-header close, mid-body close, malformed chunked, oversized headers, slow response all check only `502` + `proxy:`.
   * Result: unrelated upstream failure passes every case.
   * Fix: assert phase-specific reason/metric: `upstream_header_incomplete`, `upstream_invalid_chunk`, `upstream_header_too_large`, `upstream_timeout`, etc.

7. **DONE: Drain contract test does not verify full body delivery**

   * `tests/http_full_drain_contract_e2e.cxx`
   * Problem: for a 16 MiB response, test checks tail is non-empty and ends with `x`.
   * Result: truncated body ending in `x` passes.
   * Fix: count body bytes already read after headers + tail bytes; assert exactly `Content-Length`.

8. **Backpressure force-close test uses too-small response**

   * `tests/http_backpressure_e2e.cxx`
   * Problem: `/large` is only 1024 bytes; drain deadline is 1 ms; metric check is `>= 1`.
   * Result: can pass due timing/metrics, not true blocked slow-consumer forced close.
   * Fix: use large unread body, small recv buffer, exact forced-close count, observable connection close.

9. **Static symlink security test only checks “not 200”**

   * `tests/file_io_http_e2e.cxx`
   * Problem: accepts any non-200 response.
   * Result: 500, malformed response, route miss, or crash-like behavior can pass.
   * Fix: assert exact expected status, e.g. 403/404, security rejection reason/metric, server still healthy.

10. **DONE: TLS external tests search whole output for `"200"`**

* `tests/tls_external.cxx`
* Problem: `openssl s_client` output is searched for `"200"` anywhere.
* Result: `"200"` in OpenSSL chatter/body/header noise can pass.
* Fix: parse the first HTTP status line and exact body.
