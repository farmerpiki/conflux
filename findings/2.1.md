Inspected current `conflux.zip`. Highest-value dedup opportunities:

## P0 — worth doing soon

1. **Generic io_uring task blocking driver**

   * Dupes: `src/file_io/driver.cxx`, `src/file_io/iopoll.cxx`, `src/socket_io/socket_io_blocking.cxx`, plus `tests/socket_task_ring_test.cxx`, `tests/udp_test.cxx`, `tests/dns_resolver_test.cxx`.
   * Repeated shape: `TaskJoinHandle<T>` → shared slot → `set_on_ready_or_run` → `submit_and_wait[_timeout]` → batch CQE dispatch → return/throw.
   * Fix: add one reusable `uring::sync_wait_task(...)` / `work::root::sync_block_on(...)` helper with:

     * ring accessor
     * completion table
     * user-data decoder
     * timeout error factory
   * Payoff: high. Reduces runtime-path drift, test helper duplication, future cancellation/timeout bug surface.

2. **HTTP client sync/async response-body logic**

   * Dupes: `src/net/client.cxx`, `src/net/client_async_impl.cxx`.
   * Exact/near dupes:

     * `follow_redirect`
     * `recv_until` / `async_recv_until`
     * `recv_exact` / `async_recv_exact`
     * `recv_to_eof` / `async_recv_to_eof`
     * `recv_chunked` / `async_recv_chunked`
   * Fix:

     * move pure redirect rewrite to `client_wire.cxx`;
     * move shared body-state policy into a small sync/async adapter: “read some” passed as callable/awaitable.
   * Payoff: high. Redirect/security/body-limit behavior should not fork between blocking and async clients.

3. **DONE: JSON boundary error/option mapping**

   * Dupes: `src/json_native_provider.cxx`, `src/json_reflect_provider.cxx`.
   * Repeated: `JsonStage → ErrorStage`, `JsonIssueCode → ErrorCode`, source mapping, dump options mapping.
   * Fix: export/reuse one boundary detail mapping block, or have reflect provider call native provider’s detail mapping directly since it already imports `conflux.json.native_provider`.
   * Payoff: high. Error taxonomy drift is expensive.

4. **DONE: JSON builder append/insert primitive construction**

   * Dupes: `src/json_builder.cxx`.
   * Repeated across `ObjectBuilder::insert_*` and `ArrayBuilder::append_*`:

     * active/committed checks
     * UTF-8 validation
     * string node creation
     * number lexeme storage
     * i64/u64/f64 `to_chars` node creation
     * child object/array setup
   * Fix: internal helpers:

     * `array_active_or_error(frame)`
     * `append_node(frame, node)`
     * `make_owned_string_node(state, sv)`
     * `make_borrowed_string_node(state, sv)`
     * `make_i64/u64/f64_node(state, value, label)`
     * `begin_child(parent_kind, state, depth, ...)`
   * Payoff: high. This file is correctness-heavy; smaller helpers reduce missed edge-case fixes.

5. **SIMD algorithm duplication between stdx/std26 backends**

   * Dupes:

     * `src/simd_std26.cxx` ↔ `src/simd_stdx.cxx`
     * `src/json_simd_std26.cxx` ↔ `src/json_simd_stdx.cxx`
   * Repeated algorithms: ASCII lower, constant-time eq, URL scan, WS unmask, JSON special-char scan, dump-safe scan.
   * Fix: backend traits layer:

     * `load/store`
     * `any`
     * `first_true`
     * `select/where`
     * `reduce_or`
     * shared templated algorithm body compiled per backend.
   * Payoff: medium-high. Keep generated code equivalent; verify with current SIMD tests/benches.

## P1 — good cleanup, lower runtime risk

6. **Benchmark io_uring/file fixtures**

   * Dupes: `benchmarks/file_io_fixed_bench.cxx`, `file_io_sqe_storm_bench.cxx`, `storage_read_bench.cxx`, `uring_timeout_bench.cxx`.
   * Repeated: `pack_ud`, `Config parse_args`, temp file, file seeding, `pump_until_count`, CQE dispatch loop.
   * Fix: extend `bench_common.cxx` with `BenchUringConfig`, `bench_parse_uring_args`, `bench_pump_cqes`, `BenchTempFile`.
   * Payoff: high for benchmark maintenance, low production risk.

7. **HTTP benchmark/test server helpers**

   * Dupes:

     * `tests/support.cxx`
     * `tests/external_support.cxx`
     * `benchmarks/http_server_bench.cxx`
     * `benchmarks/http_server_concurrency_bench.cxx`
     * `benchmarks/send_zc_bench.cxx`
     * `benchmarks/slow_consumer_backpressure_bench.cxx`
     * `benchmarks/static_strategy_matrix_bench.cxx`
   * Repeated: `wait_for_server`, `ServerHandle`, loopback connect, SIGPIPE setup, startup config.
   * Fix:

     * tests: `conflux.tests.net_support`;
     * benches: `bench_http_common`.
   * Payoff: medium-high. Avoids flaky startup behavior drifting across benches/tests.

8. **DONE: Compile-fail CMake boilerplate**

   * Dupes: `tests/CMakeLists.txt`.
   * Repeated: `add_library(... EXCLUDE_FROM_ALL OBJECT ...)`, `target_link_libraries`, `add_test(check-compile-fail-target.sh ...)`, labels.
   * Fix: `conflux_add_compile_fail_test(NAME ... SOURCE ... LINK ... EXPECT ...)`.
   * Payoff: high for adding future API-surface tests.

9. **Top-level CMake module-library declarations**

   * Dupes: `CMakeLists.txt`.
   * Repeated: `add_library`, `target_sources(FILE_SET CXX_MODULES)`, `BASE_DIRS`, `target_link_libraries`, feature gates.
   * Fix: helper like:

     * `conflux_add_module_library(TARGET ... PUBLIC_MODULES ... PRIVATE_SOURCES ... PUBLIC_LINKS ... PRIVATE_LINKS ...)`
   * Payoff: medium. Do after current CMake churn settles; helper must not hide module/header-mode edge cases.

10. **HTTP server partition prelude**

* Dupes: `src/net/http_server_{state,h2,tls,send,ws,recv,cqe,diag,loop,impl}.cxx`.
* Repeated: same POSIX/OpenSSL/nghttp2 includes and imports.
* Fix: private prelude include for global-fragment C headers, maybe separate private module for common exported/imported declarations.
* Payoff: medium. Reduces drift/noise, not much compile-time gain.

11. **Route verb accessors**

* Dupes: `src/net/app.cxx`, `src/net/router.cxx`, `src/net/http_app_json.cxx`.
* Router already has `RouteVerbAccessors`; App has repeated `get/post/put/patch/del/options` plus fixed-string variants; JSON routes duplicate Router/App methods.
* Fix:

  * generalize verb helpers with explicit-object parameter;
  * factor JSON route/app wrappers through a tiny target policy: `{ add(...) -> Router& }` vs `{ add(...) -> App& }`.
* Payoff: medium. Improves API maintenance, little perf relevance.

12. **DONE: Compression zlib/zlib-ng wrapper**

* Dupes: `src/net/compress_backend_zlib.cxx`, `src/net/compress_backend_zlibng.cxx`.
* Fix: small zlib-like traits wrapper.
* Payoff: low-medium. APIs differ enough that clarity may beat dedup here.

## P2 — mostly scaffolding/examples

13. **Quickstart/example overlap**

* Dupes:

  * `examples/quickstart/json_crud.cxx` ↔ `json_reflect_crud.cxx`
  * `examples/static.cxx` ↔ `examples/quickstart/static_files.cxx`
  * some advanced examples share `display_path(JsonError)` and tiny HTTP setup.
* Fix: only dedup helper utilities that are not part of the teaching path.
* Recommendation: keep many examples self-contained; duplication is often better for docs.

14. **DONE: Fuzz harness setup**

* Dupes: `fuzz/fuzz_json5.cxx`, `fuzz/fuzz_json_parse.cxx`, plus cookie/multipart harness patterns.
* Fix: shared fuzz driver helpers for “parse bytes with options”.
* Payoff: low-medium.

15. **API-surface smoke sources**

* Dupes: module/header compile-fail tests differ mostly by import/include and expression.
* Fix: generate tiny sources from CMake templates or keep manual.
* Recommendation: keep manual unless count grows much more; compile-fail tests are easier to audit when explicit.

## I would not dedup aggressively

* **Examples intended for users**: self-contained examples are usually better than clever shared example libraries.
* **Backend-specific compression files**: small duplication preserves direct mapping to C backend APIs.
* **HTTP server partition imports**: dedup only as a prelude cleanup, not with fragile module-scanner tricks.
* **Hot SIMD loops**: dedup only via traits if generated code stays identical in benches.

## Suggested order

1. JSON provider mapping.
2. HTTP client redirect/body policy.
3. io_uring task blocking driver.
4. JSON builder append/insert helpers.
5. Benchmark/test support helpers.
6. Compile-fail CMake helper.
7. SIMD backend traits after perf check.
