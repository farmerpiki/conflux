Static review only — no benchmark run. Treat as candidates needing perf gates before implementation.

## Highest-confidence missed opportunities

1. **DONE: Avoid eager HTTPS redirect target allocation**

   * Current: `dispatch_request()` builds `std::string redirect_target` for every request before checking `http_redirect_to_https`.
   * Location: `src/net/http_server_dispatch.cxx:142-143`
   * Fix: move construction inside redirect branch.
   * Payoff: low-risk hot-path allocation/copy removal.

2. **Build common-header summary during header copy**

   * Current: request dispatch repeatedly linear-scans `HttpFieldsView` for `host`, `content-length`, `transfer-encoding`, `expect`, `content-type`, `cookie`, `connection`.
   * Locations: `src/net/http_server_dispatch.cxx:146-287`; linear lookup in `src/net/http_types.cxx:86-108`
   * Fix: while copying parsed headers, fill `HeaderSummary` with counts/views for hot headers.
   * Payoff: every HTTP/1 request; especially many headers or middleware-heavy apps.

3. **Remove default `Response` heap-ish costs**

   * Current: default `Response` owns `status_text = "OK"` and `content_type = "text/html; charset=utf-8"`, then many responses overwrite them.
   * Location: `src/net/response.cxx:121-130`
   * Fix: store status code only; derive reason phrase from table unless custom reason set. Store content type as enum/string_view + optional owned custom string.
   * Payoff: small response throughput, allocation pressure, cache footprint.

4. **Stop copying response body into formatted header buffer**

   * Current: `format_response()` builds one `std::string` containing headers plus text body.
   * Location: `src/net/http_server_helpers.cxx:171-252`
   * Fix: format headers separately, send headers + body via gathered send/writev-equivalent path; TLS can still serialize sequentially.
   * Payoff: JSON/text responses avoid another body copy.

5. **Make route metadata lazy by default**

   * Current: sync route dispatch adds `__conflux_route_pattern` unless `CONFLUX_ROUTER_LAZY_ROUTE_METADATA` is enabled.
   * Location: `src/net/router_dispatch.cxx:88-94`
   * Fix: default to lazy route metadata; observability can request it explicitly.
   * Payoff: avoids per-request owned-param storage on normal routes.

6. **Avoid middleware chain heap allocation per request**

   * Current: `CloneableFunction` always heap-allocates model storage; middleware dispatch constructs handler wrappers on request path.
   * Locations: `src/net/server_types.cxx:870-918`; `src/net/router_impl.cxx:579-584`
   * Fix: use move-only small-function for per-request `next`, or a stack chain cursor that does not clone/heap-allocate.
   * Payoff: apps with middleware get lower latency and fewer allocations.

## Medium-risk, high-payoff

7. **Single-pass HTTP/1 header parse + summary**

   * Current: parser does `find("\r\n")`, `find("\r\n\r\n")`, then scans lines again.
   * Location: `src/net/http1_parser.cxx:65-179`
   * Fix: one pass over header bytes: detect line boundaries, enforce limits, populate parsed headers, populate common-header summary.
   * Payoff: fewer scans; safer place to centralize smuggling/limit checks.
   * Risk: protocol/security semantics; needs fuzz + corpus replay.

8. **Exact-route fast path**

   * Current: router indexes by first literal, then still iterates candidate vectors and compares exact paths.
   * Locations: `src/net/router_impl.cxx:17-25`, `src/net/router_dispatch.cxx:74-77`
   * Fix: per-method exact path map before candidate iteration; keep existing generic/wildcard path.
   * Payoff: common REST apps with many literal routes.

9. **Replace `std::map` for HTTP/2 streams**

   * Current: `Conn::h2_streams` uses node-based `std::map`.
   * Location: `src/net/http_server_state.cxx:270`
   * Fix: flat map/vector indexed by active stream window, or reserved unordered map.
   * Payoff: fewer allocations/cache misses under H2 concurrency.

10. **Use active connection list / timing wheel instead of scanning `fd_table`**

* Current: timer/drain/shutdown scans whole `fd_table`.
* Locations: `src/net/http_server_loop.cxx:811-817`, `830-870`, `920-935`, `1238-1244`
* Fix: maintain active connection IDs + timeout wheel/min-heap.
* Payoff: many idle conns, sparse/high fd tables, shutdown scans.

11. **Segment `fd_table`**

* Current: `conn_for(fd)` resizes vector to `fd + 1`, capped at 1,000,000.
* Location: `src/net/http_server_loop.cxx:360-372`
* Fix: paged/segmented fd table.
* Payoff: avoids large sparse vector growth and default-constructing many `Conn`s.

12. **Socket coroutine op-state allocation collapse**

* Current: socket tasks use `shared_ptr<TaskSource>`, holders, weak cancel hooks, and captured completion lambdas per operation.
* Locations: `src/socket_io/socket_io_coro_impl.cxx:24-30`, `90-144`, plus repeated `make_shared` sites.
* Fix: intrusive op-state slab owned by `SocketTaskRing`; completion table stores `{op*, fnptr}` or slot index.
* Payoff: major allocation reduction for TCP/UDP/DNS/client paths.

13. **CompletionTable state model**

* Current: `CompletionTable::Slot` stores `small_move_only_function<void(IoResult)>`; larger captures spill.
* Location: `src/uring/uring_completion.cxx:17-31`, `45-74`
* Fix: typed operation slots or fnptr+context path for common operations.
* Payoff: less heap traffic, smaller CQ dispatch cost.

14. **Task control-block specialization**

* Current: task state uses `shared_ptr<ControlBlockInterface<T>>` + virtual interface for many operations.
* Locations: `src/work/root_tasks.cxx`, `src/work/root_core.cxx`
* Fix: fast control block for single-await/no-cancel internal tasks; intrusive refcount or pooled control blocks.
* Payoff: async-heavy routes and socket operations.

15. **Enable/evaluate coroutine frame pool for perf presets**

* Current: `CONFLUX_WORK_CORO_FRAME_POOL` defaults off.
* Location: `src/work/root_core.cxx:3-7`
* Fix: perf/server preset enables it; add hit/miss/size counters.
* Payoff: task-heavy workloads; low implementation cost, evidence-gated.

## JSON-specific

16. **Lazy JSON hash seed**

* Current: every `DocumentStorage` initializes `hash_seed_` via `getrandom()`.
* Location: `src/json_api.cxx:674-693`
* Fix: initialize only when object hash table/member index is built.
* Payoff: tiny JSON parse/decode paths avoid syscall/random overhead.

17. **Embed owned input in `DocumentStorage`**

* Current: owned parse allocates `DocumentStorage`, then separately allocates `std::string`.
* Locations: `src/json_api.cxx:689`; `src/json_parse.cxx:1165`, `1272-1274`
* Fix: `std::optional<std::string>` or direct `std::string owned_input`.
* Payoff: one fewer heap allocation per owned parse.

18. **Fix `string_arena.reserve(input.size())` dependency**

* Current: parse reserves string arena to full input size to prevent dangling views in duplicate-key set.
* Locations: `src/json_parse.cxx:1024-1030`, `1090-1097`
* Fix: duplicate-key tracking stores member indices/hash/offsets instead of `string_view`s into moving arena.
* Payoff: large RSS/cache improvement for mostly-borrowed JSON with few escaped strings.
* Risk: parser correctness; worth separate branch.

19. **Direct JSON body → reflected struct decode**

* Current shape appears DOM-first for normal JSON body flows.
* Fix: for `Json<T>` / `req.json<T>()`, parse directly into `T` using reflected field table, no DOM nodes/object members/string arena unless requested.
* Payoff: biggest likely JSON API win: fewer allocations, fewer lookups, less memory.

## Client/runtime

20. **HTTP client connection reuse**

* Current client path appears request-oriented, not pooled/reused.
* Fix: origin-keyed keep-alive pool, DNS cache, TLS session reuse, max idle/per-origin limits.
* Payoff: very high for client workloads; lower priority if server-first.

21. **Defer IOPOLL/static-file and RECV_ZC until evidence**

* Current proposals already mark these as evidence-gated.
* Keep as benchmark items, not implementation defaults.
* Higher-confidence server wins are above: header summary, response formatting, allocation reductions, route fast paths.

## Not worth doing first

* Broad memory-order weakening in `WorkPool`.
* Bigger SIMD tokenizer work before JSON direct-decode and arena-reserve fixes.
* More io_uring feature flags before allocation/copy/header-path cleanup.
* Branch hints/manual inlining without perf counters.

Best first benchmark target: implement items **1 + 2 + 3 + 5** together, then run plaintext route, JSON response, routed params, middleware chain, and allocation counters.
