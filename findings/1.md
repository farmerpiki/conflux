## P0

* **Async `Request const&` lifetime contract is broken**

  * `src/net/router.cxx:433-435`: creates local `owned`, then calls async handler with `owned` by `const&`.
  * `src/net/router_dispatch.cxx:193-208`: creates local `call_req`, then starts/returns route task using `call_req` by `const&`.
  * `src/net/http_server_loop.cxx:139-144`: creates local `owned`, then returns deferred context dispatch.
  * `src/net/router_dispatch.cxx:33-51`: task is wrapped into `DeferredResponse`, so it may run after those locals die.
  * Impact: any coroutine handler/middleware using `req` after first suspension can read dangling strings/fields/body.
  * Fix direction: async/context handler ABI should own `Request` for task lifetime. Pass `Request` by value/move into the coroutine frame, or wrap invocation in a coroutine that captures/moves owned request.

* **Async extractor safety gate only bans `RequestView`, not borrowed extractors**

  * `src/net/app.cxx:1988-1992`: static assert checks only `has_request_view_arg`.
  * `src/net/app_traits.cxx:282-290`: `has_request_view_arg` detects only exact `RequestView`.
  * `src/net/app.cxx:1536-1608`, `1677-1687`: `Path<string_view>`, `Query<string_view>`, `Header<string_view>`, `Cookie<string_view>`, `Form<string_view>`, `BodyText`, `BodyBytes`, `Multipart`, `RequestId`, `Bearer`, etc. borrow from request storage.
  * `src/net/app.cxx:1904-1942`: async invocation captures `&req`.
  * Impact: the contract says extractor views are handler-lifetime only; async handlers can still compile with borrowed extractors and suspend with dangling views.
  * Fix direction: reject all borrowed extractor types for `Task` handlers, or convert them to owned equivalents before invoking async handlers.

## P1

* **Context-route API bypasses route metadata/introspection/validation**

  * `src/net/app.cxx:670-719`: `add_context`, `get_context`, etc. directly call `router_.add_context`.
  * `src/net/app.cxx:982-1013`: `routes()` reads only `route_metadata_`.
  * `src/net/app.cxx:1098-1245`: `validate()` checks only `route_metadata_`.
  * Impact: context routes can be live but absent from `routes()`, `route_table()`, OpenAPI, duplicate/ambiguous-route validation, missing-state validation, and path-extractor validation.
  * Fix direction: context route registration should record metadata exactly like normal extracted routes, or the low-level direct API should not be exposed through `App`.

* **Rejection observability contract is inconsistent for early raw receive-cap overflow**

  * `docs/observability.md:45-48`: App server hooks should record parser/admission rejections into the same registry.
  * Normal path: `src/net/http_server_dispatch.cxx:46-73` emits response, increments counters, calls `observability_hooks_.rejection`.
  * Early cap path: `src/net/http_server_recv.cxx:315-326` increments `body_too_large` and writes response manually, but does not call the rejection hook.
  * Impact: passive `HttpServerMetrics::rejections.body_too_large` increments, but Prometheus/app observability can miss this rejection class.
  * Fix direction: route this path through the same rejection emitter, or call the same hook/counter helper.

* **DONE: Middleware `Next`/`AsyncNext` is mutable shared state with no one-shot contract enforcement**

  * `src/net/router_impl.cxx:507-538`: context middleware chain shares `Step::idx_`; each `next_()` call mutates the same index.
  * `src/net/router_impl.cxx:490-497`: sync middleware has the same single mutable cursor pattern.
  * Impact: middleware calling `next()` twice, concurrently, or after suspension can skip middleware/route stages unpredictably. This should fail loudly or be explicitly impossible.
  * Fix direction: make `Next` one-shot with a guard, or make each `next()` call own an immutable continuation frame.

## P2

* **DONE: `http::Request` documentation contradicts implementation**

  * `docs/cost-lifetime-model.md:15-17`: says `http::Request` is non-owning/view-shaped and cannot suspend.
  * `src/net/server_types.cxx:760-774`: `::Request` owns strings, fields, files, body.
  * `src/net/server_types.cxx:860-862`: `conflux::http::Request = OwnedRequest`.
  * Impact: docs tell users `Request` is unsafe across suspension while compile diagnostics tell async handlers to use `http::Request const&`.
  * Fix direction: document `http::Request` as owned, then fix async reference lifetime; or rename/split public aliases.

* **DONE: Body-size rejection code is not stable across server/parser vs app JSON extractor**

  * Contract/docs: `body_too_large` maps to 413 and `rejections.body_too_large` in `docs/http-server-api.md:196-217`.
  * Server rejection uses `body_too_large`: `src/net/server_types.cxx:78`, `src/net/http_server_dispatch.cxx:63-69`.
  * JSON extractor uses `content_too_large`: `src/net/app_json_helpers.cxx:161-165`.
  * Impact: clients/metrics/tests cannot rely on one stable problem code for body cap failures.
  * Fix direction: use `body_too_large` for request body cap violations; reserve `content_too_large` only for a deliberately separate response/content concept.

* **SSE/WS route registration bypasses app metadata**

  * `src/net/app.cxx:749-760`: `sse()` and `ws()` directly call router, no metadata recording.
  * Impact: live routes are absent from `routes()`, `route_table()`, OpenAPI, startup validation, and route introspection.
  * Fix direction: record metadata with handler kind `sse`/`ws`, or keep these as lower-level router-only APIs.
