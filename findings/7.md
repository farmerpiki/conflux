## P0 smells

### 1. DONE: `JsonArena` stale-document invalidation is semantically unsafe

Evidence:

* `src/json_api.cxx`
* `src/json_parse.cxx`
* `tests/json_test.cxx`

`JsonArena::parse_into`, `parse_borrowed_into`, and `parse_moved_into` reuse `storage_` and return `ArenaDocument{storage_.get(), generation_, &generation_}` but do **not** increment `generation_`. `reset()` increments it, but reparsing into the same arena does not.

Result: an old `ArenaDocument` from a prior parse still passes `check_live()` after a later parse, but now points at the new document storage. That is worse than a clean invalidation: stale handles silently observe unrelated JSON.

Also:

```cpp
std::size_t slab_used() const noexcept { return 0; }
```

That makes public allocation telemetry misleading.

Fix direction:

* Increment arena generation on every successful parse that replaces `storage_`, not just `reset()`.
* Decide/document whether an arena supports one live document or multiple live docs.
* Add a test: parse doc A, keep handle, parse doc B, verify A is invalid/rejected.
* Replace `assert`-only liveness with a release-visible checked path for public API access, or make stale access impossible by type design.

### 2. DONE: DB pool ownership model is single-threaded in `acquire()` only, not in lease return

Evidence:

* `src/db/pool.cxx`
* `src/db/connection.cxx`

`Pool::acquire()` checks owner thread. `Lease::~Lease()` calls `pool_->return_(...)`, and `return_()` mutates `idle_`, `total_`, `waiters_`, and dispatches waiters without owner-thread check or synchronization.

If a lease is destroyed on a non-owner thread, the pool’s single-thread invariant is broken. This is not a sanitizer/static-analysis style typo; it is a lifecycle/API contract smell.

Also, timeout/cancelled waiters remain in `waiters_`. The cancel hook and timeout path complete the waiter source but do not remove it from the deque. Later `try_dispatch_waiters_()` pops stale waiters and attempts dispatch. This can create queue churn, misleading pressure behavior, and memory growth under repeated timeout/cancel storms.

Fix direction:

* Make `Lease` non-sendable/non-cross-thread by construction, or marshal returns onto the pool owner executor.
* Remove cancelled/timed-out waiters eagerly, or use tombstone accounting plus bounded cleanup.
* Add pressure tests: acquire timeout storm, cancellation storm, cross-thread lease destruction.

### 3. DONE: Hidden singleton DB cancel pool is a global bottleneck/lifecycle smell

Evidence:

* `src/db/connection.cxx`

```cpp
inline WorkPool &cancel_pool() {
    static WorkPool pool{WorkPoolOptions{.threads = 1}};
    return pool;
}
```

All DB cancellation work funnels through a process-global one-thread pool. That creates hidden contention, hidden lifetime, and no app-level control over cancellation capacity. For a high-concurrency framework, this should be user/runtime-owned or pool-owned, not an invisible singleton.

Fix direction:

* Make cancel executor/pool part of DB pool config.
* Default can be one thread, but explicit and observable.
* Add metric: queued/running DB cancellations.

## P1 smells

### 4. `conflux.curated` still imports a leaky `conflux.http` façade

Evidence:

* `src/facade/conflux_curated.cxx`
* `src/net/http_facade.cxx`

The active API-surface plan explicitly wants `curated ⊂ extended ⊂ complete`, with low-level runtime/parser/router/protocol/buffer/io_uring kept out of first-contact aggregate imports.  The proposal already names this as a known risk: curated leaks internals through `conflux.http`, with Stage 2 needing a true façade. 

Current `conflux.http` exports/imports app/router/request/response/JSON and exposes concepts/aliases tied to:

* `RequestContext`
* `Router::Handler`
* `Router::AsyncNext`
* `conflux::work::Task<T>`
* `Config`
* `SseChannel`
* `WsConn`
* `RunStatus`

This means the curated path still teaches users internals early.

Fix direction:

* Split `conflux.http` into a truly boring façade and move lower-level concepts to `conflux.http.server`, `conflux.http.routing`, or `conflux.http.extended`.
* Keep direct imports available; just stop re-exporting them from curated.
* Add negative compile tests for curated not exposing router/work internals.

### 5. `http::stream` is not streaming

Evidence:

* `src/net/http_facade.cxx`

Current `http::stream(F&& writer, ...)` gives the writer a sink that appends into `std::string`, then returns `Response::with_body(...)`.

That is a full-buffer response helper with a streaming-shaped name. It hides allocation, loses backpressure semantics, and teaches the wrong mental model.

Fix direction:

* Rename current helper to `buffered_stream`, `body_builder`, or remove from curated.
* Reserve `stream` for real incremental send/backpressure-aware response.
* Add doc badges/cost labels: copies, allocates, blocks.

### 6. `http::file` is blocking full-buffer I/O behind a cheap-looking helper

Evidence:

* `src/net/http_facade_extended.cxx`

`http::file(path)` calls `blocking_read_text_file(..., max_size_t)` and builds a normal body response. Even in `extended`, the name implies efficient file serving, but behavior is blocking + full-buffer.

Fix direction:

* Rename to `blocking_file_response` or `read_file_response`.
* Provide separate `file_send`, `static_file`, or `mapped_file` APIs for zero-copy/async paths.
* Put blocking file helper behind explicit blocking namespace or config.

### 7. DONE: Normal handler shape makes accidental ring-thread blocking too easy

Evidence:

* `src/net/app.cxx`
* `todo/server_gaps.md`

Current direction says handlers run on ring threads unless users explicitly offload; no hidden sync-handler auto-offload. That is coherent, but ergonomic hazard remains: the easy sync handler shape invites DB calls, filesystem calls, CPU work, or sleeps on the event loop.

Fix direction:

* Make docs/examples strongly bias toward async/offload for nontrivial work.
* Name escape hatches explicitly: `run_blocking`, `offload`, `blocking_io`.
* Add runtime debug guard/telemetry for handler duration on ring threads.
* Expose a “no hidden blocking” contract in docs/tests.

### 8. Header bridge is a second C++ frontend made of regexes

Evidence:

* `scripts/module_header_bridge.py`
* `cmake/ConfluxHeaderInterface.cmake`

The bridge parses/transforms modules into headers with regexes and special-case collision rewrites. This is practical for now, but it is a deep maintenance smell: each new public API feature increases the chance that module and header modes silently diverge.

The API-surface proposal already calls out module/header parity and avoiding public API drift as goals.  Current smoke coverage does not yet prove that for the whole surface.

Fix direction:

* Generate profile modules, headers, docs, and smoke tests from one manifest.
* Add exhaustive public import/include smoke tests for every documented public module/header.
* Add mixed consumer test: one TU imports, one TU includes, linked together.
* Add API-shape drift snapshots for curated/extended/complete.

### 9. DONE: Mock/http-api build does not actually smoke HTTP public headers

Evidence from build:

* `CONFLUX_FEATURE_SET=http-api`
* `CONFLUX_USE_MOCK_LIBURING=ON`
* runtime/http installed package components disabled
* generated many headers, but hygiene smoke checked only 11 core public headers

This creates false confidence for the exact mode used in sandbox/build automation.

Fix direction:

* Add a compile-only header smoke lane for HTTP façade/profile headers even when runtime binaries are disabled by mock liburing.
* Separate “cannot run HTTP runtime” from “cannot compile HTTP public API.”
* Make smoke output list which public surfaces were skipped and why.

## P2 smells

### 10. Build feature/provider logic is duplicated between normal and header-interface paths

Evidence:

* `cmake/Dependencies.cmake`
* `cmake/ConfluxHeaderInterface.cmake`

Provider discovery and feature availability are partially repeated in header-interface CMake. That can make module mode and header mode disagree about TLS/HTTP2/HTTP3/compression/DB/etc.

Fix direction:

* Centralize provider resolution into one source of truth.
* Header-interface path should consume resolved feature/provider facts, not rediscover them.
* Add configure-time test that module/header feature macros match for same input flags.

### 11. DONE: WebSocket path uses blocking/per-connection thread semantics inside a high-perf server

Evidence:

* `src/net/http_server_ws.cxx`
* `src/net/realtime.cxx`

Comments explicitly describe SSL ownership moved to `std::thread` and blocking I/O as correct for WS thread path. This may be acceptable as an implementation stage, but as public surface it clashes with the io_uring/reactor identity and makes backpressure/scalability story harder.

Fix direction:

* Clearly classify current WS implementation as blocking-thread backend.
* Keep it out of curated if possible.
* Add explicit queue/backpressure metrics for WS sends.
* Long-term: ring-native WS send/receive path or documented backend choice.

### 12. Response helpers hide allocation/copy cost

Evidence:

* `src/net/response.cxx`
* `src/net/http_facade.cxx`

`text`, `html`, `json`, `stream`, `file` all converge toward owned `std::string` body responses. That is fine for ergonomics, but for Conflux’s identity the cost model should be visible. The project guidance emphasizes ownership/lifetime documentation and views in hot APIs. 

Fix direction:

* Add explicit variants: `response::owned`, `response::borrowed/static`, `response::file`, `response::stream`.
* Keep simple helpers, but document them as allocating/copying.
* Add allocation counters for response body construction.

### 13. DONE: Build metadata has feature drift

Evidence:

* `src/types_api.cxx`

`BuildInfo::json_reflect` appears tied to `CONFLUX_HAS_JSON != 0`, not a reflection-specific macro. That makes public metadata less trustworthy.

Fix direction:

* Split `json` availability from `json_reflect` availability.
* Add build-info smoke tests across feature sets.
